## 0. 已定决策（2026-11-21，Asia/Taipei）

Cuber 于 2026-11-21 拍板如下三条，本文自此按此定稿，不再作为待选项：

1. **名字与世界观用翠谷套。** 对外游戏名是《翠谷奇谭》（Tale of the Verdant Vale）。地名、人物、怪物、技能、货币一律用公开主线名称，不用绒芽谷 / 露珠镇 / 果果婆婆 / 雾核兽等。完整对照见 §0.1。
2. **主线仓库是公开的 `cuberqiu/maple-adventure`。** 把 `maple-adventure-cursor` 的 `q-style-reskin` Q 版贴图与渲染方式合入该仓。旧存档视为新档，不迁移、不兼容读取（存档键处理见 §14 与交接文档）。

## 1. 设计定位与风格关键词

本路线把《翠谷奇谭》的美术从「960×540 代码绘制」改为「480×270 位图贴图 Q 版」。贴图与渲染骨架来自 `q-style-reskin`，对外名称与世界观以翠谷主线为准。

【出处：visual-style】已批准方向：明亮、厚实、糖果感的 Q 版（chibi）卡通。大头、粗描边、软赛璐璐（cel）分色、高光发亮。整体要软、圆、友好——不要锐利的像素锯齿。

推荐对内关键词（可写进素材 brief）：

- **Q 版糖果风**：大头短身、圆润轮廓、可读剪影。
- **厚描边 + 赛璐璐分色**：2～3 档固有色，不要写实渐变和照片滤镜。
- **釉面高光**：按钮、药水、浆果、眼睛有块状高光，而不是漫反射。
- **绘制感，不是像素风**：位图本身可以是高分辨率绘画，再按 `displayH` 缩小到逻辑高度；禁止把 nearest-neighbour 当成风格。
- **奶油木与叶绿**：UI 是奶油面板 + 深木描边 + 叶绿主按钮；世界是暖日光的露水镇、翠叶林地、幽苔洞窟。

一句话定位：**「把手绘 Q 版角色和场景，用平滑缩放贴进 16:9 的小舞台，再用糖果木质 UI 包起来。」**

## 2. 画布、网格与缩放

### 2.1 逻辑舞台

- 内部画布固定 **480×270** 逻辑单位（`VIEW_W` / `VIEW_H`），比例 16:9。【出处：visual-style】
- 世界坐标与逻辑画布 1:1。角色碰撞盒小于立绘（刻意为之，Q 版「画比盒子大」）。【出处：visual-style】
- 摄像机对 `camera.x / camera.y` 做 `Math.round`，再平移；禁止亚像素抖动。实现已如此。
- 精灵锚点：**底部中心**对准碰撞盒底边中心 `(x + w/2, y + h)`，按清单中的固定 `displayH` 等比缩放。【出处：visual-style】
- 源文件朝向：角色朝右，Boss 朝左；反向用 `ctx.scale(-1, 1)`。【出处：visual-style】

### 2.2 缩放（实机，与「整数倍缩放」的关系）

实现（`public/js/main.js` `resize()`）是：

1. 若 `pointer:coarse` 或窗口宽度 ≤ 900，给 `body` 加 `touch`，底部预留 **168px** 给触控层；桌面预留 **28px** 给页脚提示。
2. `scale = min(innerWidth / 480, (innerHeight - bar) / 270)`，**连续比例**，不是整数倍。
3. CSS 显示尺寸 = `floor(VIEW * scale)`，保证整像素，但不保证是 480/270 的整数倍。
4. 后备缓冲：`backing = clamp(ceil(devicePixelRatio), 2, 4)`，`canvas.width = VIEW_W * backing`。
5. `ctx.imageSmoothingEnabled = true`，`imageSmoothingQuality = 'high'`；CSS `image-rendering: auto`。【出处：visual-style：绘制风，禁止 nearest-neighbour】

【冲突 / 任务要求澄清】本路线**不是像素画**，因此「整数倍缩放 + 关闭 image-smoothing」与 `visual-style.md` 和现实现相冲突。推荐规范：

- **必须**：统一等比缩放，保持 16:9，不为了铺满而拉伸（本分支已做到，旧翠谷竖屏 16:10 拉伸已废弃）。
- **必须**：平滑缩放，禁止 `image-rendering: pixelated` / nearest-neighbour。
- **必须**：摄像机与绘制坐标像素对齐（`round`）。
- **建议**：在连续 scale 之上优先选「不大于可用空间的最大整数倍」（1× / 2× / 3× / 4×），余量用页面 letterbox 消化，减少非整数倍带来的轻微发糊；缓冲倍率仍按 DPR。若整数倍导致舞台过小（尤其横屏手机），允许退回当前连续 scale。
- **不要**把 HUD 的 CSS 像素尺寸当成逻辑单位；HUD 目前按 CSS px 固定，不随画布整数倍放大，窄屏会相对过大——见审计 P0。

页面背景是窗外 letterbox（奶油橙到湖绿径向渐变 `#EAF6E0`），舞台本身是带 4px `--ink` 描边、16px 圆角的画布。触控层是 `#stage` 的**兄弟节点**，不覆盖画布。【建议】保持这条，不要回到「按键贴在 canvas 上」的旧方案。

金币、药剂不要为了贴近 token 重绘；若要对齐，优先**改 token 注释为「语义近似」**，或在 UI 里继续用 token、世界掉落用原图。

## 6. 字体

【出处：visual-style】栈为：

```
"Baloo 2", "Nunito", "PingFang SC", "Hiragino Sans GB",
"Microsoft YaHei", "Noto Sans SC", system-ui, sans-serif
```

字重：HUD 数字与标题 700–800，正文 600。画布与 DOM 已共用同一栈（比旧翠谷「DOM 一套、canvas `system-ui`」进步）。

**这不是像素字体，也不应改成像素字体。** Q 版是平滑圆体。中文不会走 Baloo / Nunito（二者几乎无汉字），会回退到苹方 / 冬青黑体 / 微软雅黑 / Noto Sans SC。

【冲突 / 实机】`index.html` **没有**引入 Google Fonts 或本地 `Baloo 2` / `Nunito` 文件，注释所谓「不必下载、优雅降级」在缺字体的机器上等于直接中文黑体。实机标题与正文看起来是系统圆黑/黑体，不是 Baloo 的拉丁圆体。

【建议】

1. 若要坚持文档里的圆体：本地托管 `Baloo 2`（拉丁、数字、标题拼音）+ `Noto Sans SC` 或思源黑体（中文），用 `@font-face`，`unicode-range` 分开，加载完成前用系统字体避免闪烁。
2. 若接受「全中文界面用系统黑体」：从栈里拿掉 Baloo / Nunito，避免拉丁数字和汉字不是同一家族。
3. 不要把中文描进 PNG。标题「翠谷奇谭」、按钮、对话全部是 DOM 或 canvas 实时字。
4. 画布字号参考：伤害 13px、名牌 11px、Boss 名/血量 11–10px（逻辑像素）。HUD DOM：条内标签约 11–12px，标题 52/36px。

## 9. 响应式与触控（按 2026-11-21 决策 3 定稿）

### 9.1 原则

- 舞台**永远 16:9**，不为铺满屏幕而拉伸（禁止回到旧翠谷竖屏 16:10 拉画布）。
- 触控层是 `#stage` 的**兄弟节点**，贴在舞台外，不覆盖 canvas。
- 横屏**默认**仍把触控放在舞台下方（或上下 letterbox 里），**不**把「虚拟键收到左右、舞台拉满短边」当作主方案。
- 引导文案按输入方式切换（触控写「点「互动」和铃兰说话」，键盘写「按 Enter 和铃兰说话」）。`body.touch` 时隐藏页脚键盘说明。
- 仅在 `play`（以及确实需要移动的状态）显示虚拟键；标题 / 帮助 / 确认框必须隐藏战斗键（审计 P0-05）。
- 触控判定以 `pointer: coarse` 为主，不要只因桌面窗口宽度 ≤ 900 就强制 `body.touch`。
- 十字方向键保持标准 3×3 十字；动作键中文标签改为：血药、蓝药、翠风、晨露、互动、跳、攻击（或「风斩 / 祝福」，但不得再写「叶斩 / 芽弹」）。

### 9.2 数值（CSS 像素，按布局视口，不含 DPR）

逻辑舞台仍是 480×270。页面左右上下各留 `APP_PAD = 10`，舞台与触控间距 `STAGE_GAP = 10`。桌面无触控时页脚预留 `FOOT_H = 28`。

| 常量 | 值 | 含义 |
|---|---|---|
| `TOUCH_H_MAX` | **168** | 触控区最大高度。舒适档：十字三行 + 动作两行，键约 52×52，间距 6 |
| `TOUCH_H_COMFORT` | **128** | 缩间距、键约 46px 的常规压缩档 |
| `TOUCH_H_MIN` | **72** | 默认计算时先给舞台让路后的最小触控高度。单行或极紧凑十字，键高约 44 |
| `TOUCH_H_EMERGENCY` | **56** | 短边极小时的退化：只保证十字 + 跳 + 攻击；药剂 / 技能改用舞台内状态钮或二次面板 |
| `STAGE_H_PREFERRED` | **270** | 希望达到的舞台 CSS 高度（1× 逻辑像素） |
| `STAGE_H_MIN` | **180** | 舞台最小高度（2/3×）。再低则 HUD 不可用 |
| `STAGE_W_MIN` | **320** | 与 180 对应的 16:9 宽度 |

触控高度上限是 168，**禁止再出现「先扣 168 再算 scale」**——那会在 844×390 一类横屏上把舞台压到约 0.82× 的邮票（见 `13-mobile-landscape-ingame.png`）。

### 9.3 分配算法

```
availW = innerWidth  - 2 * APP_PAD
availH = innerHeight - 2 * APP_PAD

若无触控：
  scale = min(availW / 480, (availH - FOOT_H) / 270)

若有触控：
  1. 先按触控只占 TOUCH_H_MIN 来给舞台让路：
       maxStageH = availH - STAGE_GAP - TOUCH_H_MIN
       scale = min(availW / 480, max(0, maxStageH) / 270)
  2. stageW = floor(480 * scale)，stageH = floor(270 * scale)
  3. leftover = availH - stageH - STAGE_GAP
     touchH = clamp(leftover, TOUCH_H_MIN, TOUCH_H_MAX)
     多余高度归页面 letterbox，不要把触控拉过 168。
  4. 若 stageH < STAGE_H_MIN：进入 §9.4 退化。
```

用这个算法，先前出问题的 844×390 横屏约为：`availH ≈ 370`，`maxStageH ≈ 288`，`scale ≈ 1.07`，舞台约 512×288，触控 72——舞台接近 1×，而不是 394×222 的邮票。竖屏 390×844 仍受宽度限制，舞台约 370×208，触控可以回到 168，与现在接近。

缩放仍为统一等比、CSS 尺寸取整、`imageSmoothingEnabled = true`、`imageSmoothingQuality = 'high'`。整数倍优先仍是 §2.2 的建议，但不能为了凑整数倍而跌破 `STAGE_H_MIN`。

### 9.4 短边很小的退化策略

按顺序降级，能停在上一级就不要往下走：

1. **压缩触控**：`touchH` 落在 72–128，键缩小到 46px，间距 4。
2. **紧急触控 56px**：只保留十字 + 跳 + 攻击；血药 / 蓝药 / 技能靠舞台内快捷栏或一个「技能」面板。
3. **仍低于 `STAGE_H_MIN`（多见于极扁横屏）**：允许一次退化，把触控改到左右 letterbox（左十字、右动作，单侧宽度不超过 `min(136, 侧边剩余)`），高度不再从短边扣除，舞台按 `min(availW - 两侧触控, availH)` 的 16:9 计算。这不是默认横屏布局，只是保底。
4. **连保底都不够**（舞台仍 < 180 或宽 < 320）：保持 16:9，允许页面在主轴上滚动以露出触控；不要拉伸舞台。此时启用紧凑 HUD（§9.6）。

### 9.5 标题卡：必须露出主按钮

标题 / 帮助 / 确认卡片**不要再以 `#stage` 的高度作为 `max-height` 上限**（这是 P0-01 的根因：竖屏舞台约 208–219px，卡片把导语和声明排满后裁掉「继续旅程 / 新的旅程」）。

定稿要求：

- 这些卡片挂在 `#app`（相对视口），不要裁在舞台框里。
- `max-height: calc(100dvh - touchH - 24px)`。标题态虚拟键隐藏，此时 `touchH = 0`，即大约 `100dvh - 24px`。
- 宽度保持 `min(440px, 100% - 20px)`。
- **主 CTA 钉在卡片底部**（继续旅程、新的旅程、确认框的是 / 否），正文再长也只滚中段，按钮不得滚出首屏。
- 过长的原创声明可以折叠或放在可滚区域。
- 竖屏可以把 16:9 舞台当作卡片后的背景插画，或缩在卡片上方；两者都可以，但按钮必须完整可见。

验收视口：390×844 竖屏、844×390 横屏，不滚动就能看到两个主按钮。

### 9.6 小舞台上的 HUD

当舞台 CSS 高度 < 270（竖屏宽度受限时必然发生）或触控可见时：

- 姓名行不写主角名，只保留地图名（如「露水镇」），单行省略，不得折行撞等级徽章。
- 提示条放到舞台外（触控上方）或缩成单行，不得横挡角色。
- 触控可见时，隐藏舞台内四颗技能圆钮，或改成不可点的状态灯，避免与下方文字键重复（并缓解 P0-03）。
- 右上金币 / 背包 / 暂停 / 静音不得压住关键 NPC。

## 10. 可访问性

现状与要求：

- 焦点：标题按钮是原生 `<button>`，可 Tab，但 `user-scalable=no` + `maximum-scale=1` 阻止双指缩放，伤害弱视用户。【建议】去掉 `user-scalable=no`，改用防止意外滚动的 `touch-action`。
- 对比：ink 在奶油上够；Boss 条上的深色数字「420」叠在 `--boss` 紫上偏弱，名牌又压在条上。HP/MP 白字 + ink 描边尚可。EXP 无数，只有「EXP」。
- 动效：受击闪白短；全屏震动已关。尊重 `prefers-reduced-motion` 尚未实现——【建议】减弱飘字缩放、传送门脉冲、跑循环可保留。
- 声音钮只有图标（外加「音」字叠图），没有 `aria-pressed`。【建议】补「声音开/关」可访问名。
- 画布本身对读屏是一块位图；关键状态（死亡、商店、暂停）已在 DOM 卡片里，这是对的。胜利却只有 toast，读屏容易错过。
- 触控键 52px（窄屏 46px），接近 48px 建议值；若舞台被压得过小，画布内 48–64px 技能钮会过近——这正是 §9 要避免的。

## 11. 空 / 错 / 加载状态

- **加载**：标题卡在素材 `loadAssets` 期间禁用主按钮，有进度条 + 百分比文案（`#load-text`）。【建议】失败时给「重新加载」而不是永远停在 0%。
- **缺图**：`getImage` 失败则回退到程序绘制（旧代码绘制风）。Q 版验收应把回退当成错误态，开发期打日志，正式包不允许长期回退。
- **空存档**：「继续旅程」禁用。禁用态仍像一颗按钮，只是发灰，容易误以为坏了（旧审计仍成立）。【建议】无存档时隐藏「继续」，只留「新的旅程」。
- **空背包**：4×4 空槽保留，统计区仍显示等级与属性。不要把网格藏掉。
- **买不起**：商店「买」应禁用并说明差多少；需确认实机文案是否明确（【建议】写「还差 N 露珠」）。
- **读档失败**：toast「存档读不出来，请开始新的旅程」，回到标题。保留。
- **死亡**：卡片 + 「醒过来了」。保留按钮，不要回到旧翠谷的纯等待复活。
- **Boss 已击败**：不再生成磐苔巨像；回镇商店出现「领取谢礼」。但商店对白仍可能沿用旧句（截图里甚至是绒芽谷的「幽苔洞窟最里面睡着磐苔巨像」）。【必须】按 `bossDefeated` 切换对白，并且一律用幽苔洞窟 / 磐苔巨像。
- **胜利 / 升级**：只有短 toast，缺少可停留的成功态。【建议】至少给一条可关闭的结算卡（杀戮文案、掉落、经验），升级给横幅或卡片。

货币名称统一为「露珠」。加载、商店、错误 toast、飘字都不要出现「露珠」或其它货币名。

## 12. 新增素材验收清单

每张新图或替换图必须同时满足：

1. **路径与命名**符合 §5，主题 id 只在 `town|wild|cave`，文件名全小写。
2. **格式**：远景可用 JPEG（不透明）；其余必须是透明 PNG，不要垫实底。
3. **画幅**：同一角色全帧宽高一致，脚底基准线对齐；不要再出现「待机 117×153、跑 91×155」这类漂移。
4. **朝向**：角色朝右，Boss 朝左。
5. **描边**：不断线、不发虚；UI 用 `--ink`，世界可用角色专属深色，避免大面积纯黑。
6. **分色**：2～3 档固有色 + 一块釉面高光；不要照片写实、不要像素锯齿风格。
7. **透明边**：主体四周留 2–4 源像素透明，避免裁切描边。
8. **密度**：缩小到对应 `displayH`（主角约 48、NPC 46、小怪 30–34、Boss 96）后，五官和道具仍可识别。
9. **禁烘焙字**：UI 图、技能钮、图标里不得出现汉字或键位字母。
10. **调色**：新图与 §3 家族一致（奶油木、叶绿、雾紫、洞窟青辉），不要引入一套新的主色。
11. **地面 / 背景**：远景能横向无缝平铺；地面条顶部有清晰走跳边，底部颜色接近 `GROUND_FILL`；近景不要自带一条会错位的地面（已用 `NEAR_CROP` 规避）。
12. **平台图**：左右 48px 帽可切片，中段可重复。
13. **清单**：每加一张就更新 `docs/asset-manifest.md` / `.json`（张数、宽高、`displayH`）。
14. **回退**：正式包不得依赖程序绘制回退；缺图视为构建失败。
15. **性能**：背景单张建议保持与现图同级（中近景已约 0.5–1.2MB，不宜再堆更大的无压缩 PNG）。
